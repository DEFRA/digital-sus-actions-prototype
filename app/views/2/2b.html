2b. Design for lightweight digital pages, notifications and documents

Reducing the size of digital pages, notifications and documentation impacts the data that needs to be stored and then transferred to an end user device, in turn reducing energy consumption.

Lead role families: Design Software

Likely co-benefits: Accessibility, inclusivity, user experience

(i) Set page weight budgets

A page weight budget is an upper limit of the size of a webpage, measured in bytes.

Larger webpages mean more data transfer, and with it an increase in energy consumption.

A page budget can bring sustainability benefits as it helps:

  • Encourage designing for lightweight pages by making page weight a constraint that designers, developers and content teams consider throughout delivery
  • Prevent page weights creeping upwards as new features, media and technologies are added
Read more about implementing this point
  • Has the Design Team Set A Page Weight Budget? Sustainable Web Design
  • How to Set a Page Weight Budget Wholegrain Digital
Co-benefits and trade-offs

Co-benefits

Alongside sustainability benefits, setting a page weight budget brings co-benefits in terms of:

  • Inclusivity: Budgets encourage close consideration of what is essential for users with small screen sizes or low bandwidth, helping ensure that pages work for users with slow connections

(ii) Design for text-based journeys

Design webpages and user journeys as 'text-based' first. This means that all core content and tasks can be understood and completed without the need for images, videos or other media to communicate the steps involved.

Designing for text-based journeys also supports the the principle of 'progressive enhancement'.

Read more about implementing this point
  • GOV.UK Service Manual, Build a robust frontend using progressive enhancement
  • W3C, Web Sustainability Guidelines, 3.10 Ensure layouts work for different devices and requirements
Co-benefits and trade-offs

Co-benefits

Alongside sustainability benefits, designing for text-based journeys brings co-benefits in terms of:

  • Inclusivity: Improved performance on slower connections and older devices, extending the useful life of hardware and reducing pressure to upgrade
  • Accessibility: Well-structured text works effectively with screen readers, zoom, translation and different device types

See also: 3b.(i) Develop for progressive enhancement

(iii) Take a lean approach to multimedia and interactive content

Multimedia content such as photos and videos, and interactive elements such as maps, can add significantly to the 'weight' (the size in bytes) of a page.

Only use multimedia and interactive content when there is a clear user need, and allow users to make explicit choices to access multimedia and interactive content, rather than loading it by default.

Read more about implementing this point

W3C, Web Sustainability Guidelines (September 2026 update)

Co-benefits and trade-offs

Co-benefits

Taking a lean approach to multimedia brings co-benefits in terms of:

  • User experience: Pages load faster for all users
  • Inclusivity: Pages with less mulitmedia and interactive content function better for users with slow connections

See also: 3b.(v) Utilise lazy loading

(iv) Design for lightweight and flexible notifications

Notifications, such as emails or texts, involve data transfer and energy consumption. This can increase when they have attachments, and for services with many users these impacts can quickly mount.

Take a lean approach to notifications by:

  • Only sending emails, Short Message Service (SMS) texts, and web notifications when genuinely needed
  • Keeping notifications as lightweight (as small a file size) as possible
  • Setting up notifications so users can turn them off or choose how often to receive them according to their preference
Read more about implementing this point
  • W3C, Web Sustainability Guidelines, 2.12 Avoid unwanted notifications
Co-benefits and trade-offs

Co-benefits

Designing for lightweight and flexible notifications brings co-benefits in terms of:

  • User experience: Lightweight and simple notifications make messages quicker to understand, and easier to read on mobile devices
  • Accessibility and inclusivity: Simple, text-based messages are more likely to work across a range of device types, assistive technologies and slower connections

(v) Choose lightweight publishing formats for documents

The file format of documents impact file sizes, and the energy consumption coming from their transfer.

For example, publishing documents as well-designed HyperText Markup Language (HTML) webpages rather than Portable Document Format (PDF) can avoid unnecessary document downloads and reduce the amount of data transferred, particularly where PDFs contain large images or complex layouts.

Choose document formats with lower filesizes and more flexibility where possible.

Read more about implementing this point
  • Why GOV.UK content should be published in HTML and not PDF, Neil Williams, Government Digital Service Blog
  • A guide to publishing in html, Information Access Group
Co-benefits and trade-offs

Co-benefits

Choosing lightweight publishing formats brings co-benefits in terms of:

  • Accessibility: Semantic HTML works more reliably with screen readers, keyboard navigation, text resizing and user-defined styles than PDFs
  • User experience: Users can quickly read content directly in the service rather than downloading and opening a separate document
