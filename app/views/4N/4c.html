4c. Ensure cloud services are efficiently provisioned

Taking advantage of the various ways to maximise the efficiency of cloud computing helps ensure that energy use is reduced as far as possible

In general, Cloud technologies are energy-efficient and scalable, significantly reducing e-waste and carbon emissions. GreenOps is the practice of minimizing a cloud environment’s carbon footprint through the efficient use of cloud resources.

Adopt approaches to ensure high server utilisation and compute efficiency and avoid overconsumption of resources, including energy and associated carbon: choosing cloud infrastructure wisely can help reduce energy and water consumption, embodied carbon as well as reduced financial costs. A well-architected service is more energy-efficient. For example, Ensure we are utilising the full benefits that public cloud has to offer by driving GreenOps including:

GreenOps is closely related to FinOps (Financial Operations), as sustainability goals often align with financial efficiency. Optimizing resources for lower emissions frequently results in lower costs. GreenOps addresses the carbon footprint of cloud infrastructure, FinOps is a cooperative approach between IT, finance and business to address resource costs’ accountability in cloud environments https://greenly.earth/en-gb/blog/industries/finops-and-greenops-how-do-they-relate Choosing software architecture such as serverless computing and other composable approaches helps guarantee flexibility, scalability and adaptability, promoting reuse and reducing costs.

(i) Apply appropriate tagging to resources

Tagging usage of cloud resources supports granular reporting and data-driven decision-making on how to reduce environmental impacts.

(ii) Right-size services

Right-sizing means aligning cloud resources with the specific needs of individual workloads, applications, or services

Monitoring workloads performance allows resources, like virtual machines and storage, to be 'right-sized' to match actual demand.

(iii) Use auto-scaling

Autoscaling automatically adds or removes cloud computing resources, such as servers or processing power, to match real-time demand.

Embracing ‘always available’ rather than 'always on', ensures that compute resources automatically scale to zero when not in use.

(iv) Use spot instances

Spot instances are unused cloud capacity that can be used at reduced prices, helping cloud providers to improve data centre utilisation.

Making use of spot instances requires workloads with flexible start and end times.

See action 4a. Design for sustainable patterns

(v) Use a service mesh only if needed

A service mesh is a dedicated infrastructure layer for handling service-to-service communication in microservices.

Further reading
  • Evaluate using a service mesh, Green Software Foundation

(vi) Utilise appropriate caching

Caching temporarily stores frequently accessed data in a designated area (called a “cache”).

This enables faster access to that data, and can reduce unnecessary data transfer, server load and energy consumption.

(vii) Move from rented Infrastructure to Platform and Serverless cloud services where appropriate

Serverless architecture means creating and running applications without having to manage infrastructure, enabling flexibility, scalability and higher efficiencies.

Further reading
  • Use serverless cloud services, Green Software Foundation

(viii) Remove unused assets

Review aged instances and decommission unused resources when these are no longer required.
