4a. Design for sustainable architectural patterns

Decisions on the approaches to architectural patterns at the design stage have a significant impact at later stages the sustainable operation of a digital service.

(i) Design for asynchronous patterns and transactions

Asynchronous patterns and transactions allow tasks to run independently of one-another, enabling efficient use of cloud resources and running workloads when there is unused capacity or when the grid is greener.

These patterns allow workloads to potentially be run when and where the grid is greener. See 4c.

(ii) Design workloads for portability

Designing for portability allows applications and data to be moved between Cloud environments. This includes between public and private cloud, or between different providers, and workloads to be run when more low carbon electricity is available.

(iii) Follow microservice patterns

A microservices architecture breaks applications into smaller, independent services. This helps with the build of composable and collaborative services, driven by events, commands and queries.

This approach enables the independent scaling of services, and more efficient allocation of compute resources.

(iv) Apply best practices for containers

Containarized architecture means packaging software into self-contained units. These can then consistently run in any environment.
