4a. Design for sustainable architectural patterns

Designing workloads to be flexible workloads enable the sustainable operation of a digital service, including porting workloads between cloud locations, running workloads when there is unused capacity or when the grid is greener

(i) Follow microservice patterns

A microservices architecture breaks applications into smaller, independent services.

This approach enables the independent scaling of services, more efficient allocation of compute resources and reduced energy consumption.

(ii) Design workloads for portability

Portable workloads are those where applications, data, and services can be decoupled from any single cloud provider or underlying infrastructure.

This allows workloads to be moved across public cloud, between computing environments with minimal code refactoring or configuration changes.

This could be between public and private cloud, on-premises or even between different providers

and workloads to be run when more low carbon electricity is available (or cheaper instances, stop instances etc?)

(iii) Design workloads for flexibility

Designing workloads for flexibility means moving away from rigid, real-time execution models to those that can optimise how computing tasks are scheduled, managed, and executed.

These patterns can help maximise efficiency and avoid reliance on peak-capacity infrastructure, allowing workloads to be scheduled when there is unused capacity or the electricity grid is at a lower carbon intensity.

Approach Description
Asynchronous patterns Decoupling a task request from its completion so the system doesn't wait for a response - allows tasks to run independently of one-another
Batch processing Grouping large volumes of data to be processed all at once, rather than one by one
Interruptible processing Designing workloads that can be paused, stopped, and resumed at any time without data loss

See points on shifting to green, and also efficient cloud practices.

Co-benefits and trade-offs

Co-benefits

Alongside sustainability impact, flexible workloads can bring co-benefits in terms of:

  • Cost: Aligning resources with actual usage optimises infrastructure costs
  • Scaling: Enables more efficient scaling strategies to be put in place

Trade-offs

Potential trade-offs may include:

  • Complexity: Introduces architectural complexity (e.g. queues, event handling, retry logic)
