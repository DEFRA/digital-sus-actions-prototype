3b. Optimise data storage

Optimising storage saves on storage and associated energy consumption.

Lead role families: Data Product & Delivery Design
Likely co-benefits Performance: Optimised data storage and management will likely improve service performance and speed
Cost: Reducing data storage volumes may also save on costs

(ii) Use appropriate data storage tiers

Storage tiers organise data into different levels of access based on how often it is used.

Choosing slower ('cold') or archive storage tiers for data that is not accessed often or required instantly saves on energy consumption.

Co-benefits and trade-offs

Co-benefits from moving data to slower storage tiers where appropriate can bring co-benefits in terms of:include:

  • Lower infrastructure costs
  • Green Software Foundation, Optimize the size of AI/ML models

Co-benefits and tradeoffs

Moving data to slower storage tiers where appropriate can bring co-benefits in terms of:

  • 'Cold' or archive storage tiers are usually cheaper that warmer ones
  • supply chains with unintended social impacts, such as labour exploitation

Make sure you have the data that is accessible, relevant and high-quality enough for your intended use of AI.

(iii) Choose the right data format

Different formats for data storage offer different levels of compression and efficiency.

For example, Parquet is a better way to store large datasets than Comma Separated Values (CSV). It uses less space, and is faster and more efficient.

(iv) Deduplicate stored data

Data deduplication identifies and removes redundant copies of data in a storage system, saving on associated energy consumption.

(v) Apply best practice for database indexing

A database index is a structure that improves the speed of data retrieval and optimises database performance.

(vi) Fit the data formatted to the expected query patterns

Query patterns are reusable templates for structuring queries to solve recurring problems efficiently.

(vii) Create permissions and access plans that minimise the amount of data load per user

Create permissions and access plans that minimise the amount of data load per user based on their actual needs.
