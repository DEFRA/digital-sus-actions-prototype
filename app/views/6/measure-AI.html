Measure the environmental impact of artificial intelligence

Measuring the environmental impact of artificial intelligence (AI) can help you find impact hotspots and identify ways to reduce them.

You can include these measurements in a wider assessment of the environmental impact of a digital service or project.

Decide what to measure

Start by measuring the energy used by the AI system. You can use this figure to estimate greenhouse gas emissions and water consumption.

A complete assessment should consider these stages of the AI lifecycle:

  • preparing and storing data
  • training and fine-tuning the model
  • running the model to produce results, known as inference
Many measurement methods focus on inference or on training and inference together. State which lifecycle stages your assessment includes.

Choose a measurement method

The method you use will depend on how you access and run the model.

  • Use hardware measurements or software instrumentation for self-hosted models.
  • Use token records or supplier reports for models accessed through public cloud services.
  • Ask the supplier for environmental data when AI is built into other software.

Measure self-hosted AI models

A self-hosted model runs on hardware that your organisation owns, rents or uses exclusively. This can include:

  • desktop computers, laptops with graphics processing units (GPUs) and edge devices
  • servers in on-premises or externally managed data centres
  • virtual machines in a private cloud
  • dedicated, single-tenant cloud infrastructure

Use a bottom-up method to estimate the energy used by a self-hosted model. You can either measure the hardware directly or estimate activity using a proxy such as token use.

Measure hardware energy use directly

Direct measurement records the power used by hardware while the model is being trained or producing results.

You can collect this information from:

  • processor, GPU and AI accelerator telemetry
  • server or rack-level power distribution unit meters
  • physical power meters
  • software that records hardware use during a model run

Use software instrumentation

Software tools can record CPU, GPU and memory use during training or inference. Some tools also estimate energy use and greenhouse gas emissions.

Example measurement tools
Tool What it measures or estimates
EcolagM The environmental impact of generative AI during inference.
EcoLogits The energy and environmental impact of generative AI models accessed through application programming interfaces (APIs).

! Warning Tools may use different system boundaries, assumptions and carbon intensity data. Record the tool, version, configuration and date used.

Use tokens as an activity-based estimate

You can use token records to estimate the energy used during inference when direct measurements are not available.

A token is a unit of text processed or generated by a language model:

Input tokens
Content sent to the model, including prompts, system instructions, conversation history, documents, code and other context.
Output tokens
Content generated by the model, such as answers, summaries, tables and code.

Record input and output tokens separately. Generating output will usually use more energy than processing the same number of input tokens.

Multiply the number of tokens by an energy-per-token factor for the model and hardware:

Estimated energy use = token count × energy-per-token factor

The factor may also be affected by model size, hardware, batching, caching, response length and the number of generation steps.

! Warning Do not apply a generic token factor without checking the model, hardware, workload and system boundary it represents.

Use published estimates carefully

Published estimates can help when model-specific measurements are not available. They should not replace measured data.

The source document includes these indicative estimates:

Indicative energy estimates per million tokens
Activity Indicative energy use
Input tokens 390 Wh
Output tokens 1,950 Wh
Cache creation 490 Wh
Cache read 39 Wh
! Warning These figures need an authoritative source and a defined methodology before they are used in published reporting.

Add data centre overhead

Hardware measurements may not include the energy used by the data centre's supporting infrastructure. This can include:

  • cooling systems, pumps and fans
  • power supplies, transformers and distribution equipment
  • lighting, security and building management systems

Use the data centre's Power Usage Effectiveness (PUE) value to estimate this overhead:

Total energy use = core IT energy × PUE

Check whether the original measurement already includes facility energy before applying PUE. This will help you avoid double counting.

Measure AI accessed through public cloud services

Public cloud AI services may charge for input and output tokens, subscriptions or dedicated computing capacity.

Common ways to access cloud AI
Approach Description
Direct model API Access a provider's model through an API and pay for the input and output tokens used.
Model as a service Access a pretrained model through cloud infrastructure and standard API endpoints.
Managed AI platform Use models and supporting services within an enterprise cloud platform.

You can estimate energy use with token records, provider reports or a top-down allocation method.

Use a top-down allocation method

A top-down method starts with the energy use or emissions of a cloud environment or data centre. It then allocates a proportion to the AI workload.

For example, you could allocate the total according to the proportion of GPU or tensor processing unit hours used by the AI workload.

Record the allocation method and explain why it represents the workload. Do not present an allocated figure as a direct measurement.

Measure AI built into other software

You may not have access to token records or hardware data when AI is part of a software-as-a-service product. Ask the supplier for evidence.

Ask for an energy efficiency benchmark

Ask the supplier for an AI Energy Score or an equivalent benchmark for the models used by the service.

Ask for measured energy data

Ask the supplier to report the energy used by training and inference. The report should define its units, hardware, locations, dates and system boundaries.

Ask for a lifecycle assessment

Ask for an attributional lifecycle assessment that follows ISO 14040 and ISO 14044.

The assessment should cover:

  1. acquiring raw materials
  2. manufacturing and assembling devices and supporting equipment
  3. preparing and storing training data
  4. research, training, fine-tuning and retraining
  5. inference, networking, idle tasks, storage and cooling
  6. reuse, disassembly, recycling and disposal

The assessment should report at least:

  • energy consumption in watt-hours or kilowatt-hours
  • greenhouse gas emissions in grams or kilograms of carbon dioxide equivalent
  • water consumption in litres or cubic metres
  • abiotic resource depletion in kilograms of antimony equivalent

If the supplier does not have a lifecycle assessment

Ask for measured data or verified estimates covering:

  • the acquisition, processing and storage of training data
  • research, training, fine-tuning and retraining for the current model
  • inference on a defined set of hardware
  • the manufacture, transport and end-of-life treatment of the hardware

Ask the supplier to report inference as a median value per token. If the model is not token-based, ask for a value per inference or another clearly defined functional unit.

Compare models before deployment

Compare models before choosing one. Use the smallest model that meets the service's accuracy, safety and performance requirements.

Example model comparison tools
Tool Purpose
AI Energy Score Rates the energy efficiency of models during inference.
ML.Energy Leaderboard Compares the energy use and performance of open-weight language models.
whatmodel.sh Compares model performance, hardware requirements, resources and price.

Convert energy use into environmental impacts

Calculate greenhouse gas emissions

Multiply the energy used by the appropriate electricity carbon intensity:

Emissions = energy use × electricity carbon intensity

Use a carbon intensity value for the location and reporting period in which the energy was consumed.

The Software Carbon Intensity for AI specification provides methods for assessing emissions from AI training and inference.

The Software Carbon Intensity for AI specification is evolving. Record the version used and explain any assumptions.

Calculate water consumption

Water use can include water consumed directly by data centre cooling and water used indirectly to generate electricity.

Use the data centre's Water Usage Effectiveness (WUE) value to estimate water used for cooling:

Cooling water consumption = IT energy use × WUE

Report direct and indirect water consumption separately. State the location, period, factor and system boundary used.

! Warning Online calculators provide estimates. Do not use them as a substitute for measured data or verified supplier information.

Record and report your method

Record:

  • the model and version
  • the hardware and data centre region
  • the lifecycle stages included
  • the measurement period
  • input and output token totals, where applicable
  • the energy, PUE, carbon intensity and WUE factors used
  • assumptions, exclusions and sources of uncertainty

Report enough information for another practitioner to repeat the calculation and understand its limitations.
