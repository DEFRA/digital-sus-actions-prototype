Software and sustainability

While software itself does not have a physical mass or produce environmental impacts directly, writing, running and supporting software code dictates how hard computer hardware has to work. This leads to:

  • Electricity use by hardware, whether in data centres, network routers or end-user devices, and the greenhouse gas emissions associated with it
  • Water usage in some data centres
  • The impacts associated with manufacturing hardware, ranging from greenhouse gas emissions to biodiversity, freshwater consumption, resource depletion and land use change from mining.

Approaching measurement

Challenges around measuring the energy use of software: https://greensoftware.foundation/articles/how-to-accurately-measure-the-energy-consumption-of-application-software/

The Software Carbon Intensity (SCI) specification is a methodology for calculating the rate of carbon emissions for a software system and is now an ISO standard (ISO/IEC 21031).

The SCI aims to help teams developing software make better, evidence-based decisions during system design, development, and deployment, that will ultimately minimise carbon emissions.
