Sustainability Action

4b. Use common architectural components

Ensuring that

Architectural components in a broader digital service (which include people, processes, physical infrastructure, data governance, and off-the-shelf SaaS products) differ from software components (which are isolated blocks of code, classes, or microservices) primarily in scope, granularity, and boundary constraints.

Lead role families: Architecture Product
Likely co-benefits Cost: Lower costs coming the storage of data

How to deliver on this action

  • (i) Build with modular components
  • (ii) Create and share modular components via library

(i) Build with modular components

Component based architecture designs software as a collection of independently deployable modules.

Building with existing, proven components saves on the resources required to build from scratch.

Co-benefits and trade-offs

Compressing data for transit can bring co-benefits in terms of:

  • Lower infrastructure costs: 'Cold' or archive storage tiers are usually cheaper that warmer ones

(ii) Create and share modular components via library

Consuming data from its primary source means accessing data from where it was first generated.

This means we can access the most up-to-date information without the need for any intermediary processing or transformation. This reduces data processing, storage and network transmission energy.
